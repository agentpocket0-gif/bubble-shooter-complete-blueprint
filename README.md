# Bubble Shooter: Classic Blast

An original Godot mobile bubble-shooter project and its six-department automated build pipeline, alongside the repository's original game blueprint and separate APK-analysis utility.

## Current game project

- Game title: Bubble Shooter: Classic Blast
- Android package: com.classicblast.bubbleshooter
- Engine: Godot 4.7.2 stable
- Android target: API 36
- Project: godot_project/
- Build pipeline: .github/workflows/autonomous_6dept_studio.yml

The game project is new code. It uses original vector art generated by tools/generate_original_assets.py and original level data generated by tools/generate_levels.py. The six-department pipeline runs the REA audit, generates game content, validates GDScript, captures nine Xvfb screenshots, checks them with OpenCV, optionally asks a vision model to inspect a sample, exports Android builds, commits generated QA evidence, and publishes a GitHub prerelease.

This is an initial playable foundation, not a store-verified production release. The first Actions run and a real-device playtest are still required. The current level validator checks structure and initial match groups; it does not prove every level's full trajectory solvability or difficulty balance.

## Run the autonomous studio

1. Open GitHub repository Settings → Secrets and variables → Actions.
2. Add GEMINI_API_KEY and/or NVIDIA_API_KEY for model routing and self-healing.
3. Add the four Android signing secrets listed in docs/BUILD_STATUS.md. A persistent upload keystore is required for Play Store AAB signing; keep it safe for all future releases.
4. Open Actions → Autonomous 6-Department Game Studio → Run workflow.

The workflow uses Java 17, Android SDK 36, Godot 4.7.2 stable, and matching export templates. It creates a debug APK and a signed AAB, then publishes the APK, AAB and QA evidence to the v5.0.0-autonomous-studio prerelease.

## Important asset boundary

The extracted resources under godot_project/assets/real_pack/ are marked publishable=false in their manifest and are not used by the new game. Do not copy them into the game, screenshots, exports or release packages. The original vector art and asset sourcing notes are in ASSET_CREDITS.md.

- blueprint/original/: original game architecture, mechanics, level, economy, audio, asset, QA, LiveOps and app-flow specifications.
- blueprint/reference/: reference reports generated by the separate APK analysis workflow.
- reference/original_game_code/: study-only reverse-engineering and sample data.
- android/: existing APK analysis utility. It is separate from the Godot game.
- docs/LEGAL_AND_SCOPE.md: asset and reverse-engineering boundaries.
- docs/BUILD_STATUS.md and GAPS.md: current implementation and outstanding work.

## Other workflow
